# 通用角色情绪 — 0.4.0

当前版本已改为通用角色插件。下文旧版本章节保留历史说明；本节的 0.4.0 行为优先。

## 0.4.0：通用角色与历史继承

联动评估优先读取聊天绑定的角色名；QQ 自动把配置的角色名传入，未指定时使用情绪设置的桌面角色名，再回退“当前角色”。对方称呼和角色昵称也用于联动评估。称呼设置移到判断设置的通用区域。全新安装的人格背景采用中性说明，已保存的自定义人格和称呼保留。情绪摘要标题去除固定姓名和性别。

插件包名、nia_* 工具名、服务/路由/存储目录和默认数据标识保持兼容。它们是内部标识，不代表角色姓名。换角色继续继承原数据时，保持原 personaId，不复制或重绑会话，也不改写旧事件中的名字。更换角色卡时，手动同步情绪设置的人格摘要；本插件不会自动覆盖用户的角色卡和摘要。

此版本不提供同时多角色运行或切换时隔离数据。136 项回归通过；设置页在隔离环境实际验证保存、刷新与旧摘要保留。更新后需重启 DSH 后端。


基于 `dsh-feiyu-mood 0.7.3` 的独立本地分支，保留独立模式会话/工作区绑定和状态记录，提供通用角色的情绪评估、联动及管理设置。

状态：已完成本地测试和隔离浏览器交互验证；尚未完成正式 DSH 窗口及真实模型、QQ 往返验证。使用本地链接安装时，更新源码后需重新加载插件或重启 DSH。 不会自动替换原插件，不会自动读取或迁移原插件的状态。


## 0.2.2 联动模式（优先阅读）

与 dsh-nia-memory、dsh-nia-qq 0.2.2 一起使用。QQ 设置中打开联动后自动绑定，不需要再把每个群和私聊加入旧“会话绑定”页。
总体情绪按 personaId 共享，定向情绪按 actorId 分开，状态有来源 eventId、已处理标记和版本号。预演与正式状态分开。
QQ 先录入可信事件、评估新变化，再让 Agent 决定是否回复；没有回复正文也能更新。转述同一事件不再计分，新安慰和道歉是新证据。
桌面手动绑定会话在回合结束后评估，供下一次回应使用；目前没有接管桌面输入的前置阶段。
同人格评估串行，提交检查版本号；跨聊天不会因为一个窗口读取状态而让其他窗口收不到。
只为本批来源人物产生定向增量；用户安慰改善整体状态和对用户的感受，不自动清除对另一人的不满。

联动使用原设置的自动判断、判断模型、人格/关系背景、可信度阈值、基线、下限与衰减。模型优先使用显式判断模型，否则读取 Agent 当前模型。
联动评估输出上限 4096 token，30 秒超时。超时/格式错误不编造变化，QQ 继续使用已有状态；失败事件不标记为已处理。
联动背景按当前对象提供共享状态；注入关闭开关有效。旧版每日注入次数和“只注入一次”的预算不应用于联动，各会话需要持续看到当前状态。
旧绑定的重复评估和重复注入会在联动挂载后跳过。未联动会话仍保留下面描述的旧行为。

联动数据由记忆服务统一持久化，位于 nia-memory/state.json 的 moods。可在“妮娅的心情 → 联动心情”查看；记忆管理页保留原始诊断数据。
“独立模式（兼容）”页只管理旧模式的分组、会话或工作区绑定。0.2.2 面板不提供手动重置情绪和修改当前情绪值；旧时间线仍保留在状态文件中。不自动把旧单对象状态猜成新的多人物情绪。
下文的逐轮事后评估、1200 token 上限、每天注入 6 次和会话分组说明，仅针对旧独立模式。
本插件不提供挂饰。

## 行为

- 12 个维度：开心、安心、亲近、心疼、担心、难过、吃醋、生气、受伤、好奇、无聊、得意。
- 不默认伴侣关系；不要求心情围着用户转；个人兴趣和活动也能产生变化。
- 允许因冒犯、敷衍或失约生气；道歉和解释可以缓和情绪，但不自动清零。
- 提到别人不自动吃醋，主动唤醒不自动等于想念或被冷落。
- 判断新增变化，允许中性回合以及原情绪延续，避免同一份情绪反复加重。
- 使用人格摘要、关系背景、此前状态、最近六条对话与当前输入/回复评估。人格摘要和关系背景可在设置里修改；不会自动读取完整角色卡。
- 提供内部情绪参考，明确不要求朗读摘要、播报数值或主动解释心思。

角色卡仍负责妮娅的完整人格、表达方式、外观和行动边界。本插件不提供长期记忆、不直接发 QQ 消息、不主动执行外部任务，也不实现好感分数。现有情绪维度表示短期状态，不能当作长期关系评分。

## 安装与切换

DSH 插件管理器支持本地目录、`file:` 和 `link:` 来源。可在插件管理界面的安装入口选择本地目录，或填写下列完整来源：

```text
link:C:/projects/dsh-role-plugins/packages/dsh-nia-mood
```

如果 `dsh` 命令已经可用，也可以运行：

```powershell
dsh plugin --profile desktop add "link:C:/projects/dsh-role-plugins/packages/dsh-nia-mood"
```

安装包在同级输出目录：`dsh-nia-mood-0.3.3.tgz`。迁移或固定版本时可使用包文件；本地开发链接依赖源目录一直存在。此插件尚未发布到 npm，不要只填写包名让管理器联网安装同名包。

首次切换建议按以下顺序：

1. 等待当前任务完成，备份原情绪插件的数据与配置。
2. 安装新插件；按宿主提示重启或重新加载。首次默认不绑定任何会话。
3. QQ 联动自动接入；桌面联动在“妮娅的记忆 → 会话接入”绑定。只有旧独立模式在“妮娅的心情 → 独立模式（兼容）”绑定。
4. 正式切换前，在原插件中解除妮娅会话的绑定，或关闭原插件的自动判断和注入；避免两套情绪同时影响同一会话。
5. 新插件验证正常后使用正式会话；联动模式按同一人格共享整体心情、按人物分别记录态度。

本版本沿用原插件的 DSH 宿主接口；参考插件文档标注其验证环境为 DSH 0.2.2-rc.3，这不是本分支的真实宿主兼容性测试结果。遇到接口变化需要按实际 DSH 版本联调。

安装依据：[DSH 官方插件管理说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/boot/plugin-manager/README.md)。

## 设置与运行

设置面板有“联动心情”“判断设置”“独立模式（兼容）”三页。QQ 联动不需要手动选择会话或工作区。所有配置修改先保留为草稿，点击底部“保存设置”后生效；支持撤销和明确的失败提示。会话与工作区下拉框支持搜索，并兼容 UUID 会话标识。

基线是情绪逐渐回落的目标，不是立即设置当前心情。联动页显示包含时间衰减的当前心情及各人物状态，每 5 秒自动刷新，最多显示一位小数。展示与对话采用同一衰减公式，仅计算副本，不改写历史、不调用模型；上次事件时间与本次计算时间分开展示。没有记录时仍显示基线参考，读取失败时明确提示当前显示的是上次读到的值。“只提供情绪”不附带事件缘由，“提供情绪及事件缘由”按来源可见性附带原因。

默认称呼为妮娅；对方称呼为用户。默认基线 70，心情下限 0，总心情半衰期 12 小时。维度半衰期：受伤 12 小时、生气 6 小时、好奇/无聊 3 小时，其余 4 小时。时间流逝只减弱强度，不生成“已原谅”“已解决”的虚构事件。

每个有效回合完成后，默认额外进行一次模型评估，使用当前会话模型或设置页指定模型，输出上限 1200 token；实际消耗还包括输入上下文。日注入额度不是评估次数上限。关闭“每轮判断心情”可停止后续评估。

评估可信度低于 55 时不更新情绪；注入可信度默认要求至少 60。显著变化门槛为总心情原始增量 3 或任一维度增量 5，每份心情每天最多注入 6 次。总心情实际变化为原始增量的三分之一，内部保留小数。

同一条变化在同一份心情里只注入一次；该份多个会话共享此额度和消费状态，不保证每个会话都会收到同一条摘要。时间线仍共享可见。首次会话背景请由角色卡和记忆系统提供。

0.1.1 已移除悬浮挂饰、挂饰设置页、图片资源和页面脚本注入。联动心情数值在设置面板查看；独立模式的历史时间线保存在原状态文件中。

## 数据与恢复

独立数据目录：`$DSH_HOME/nia-mood/`；未设置 DSH_HOME 时为 `%USERPROFILE%\.dsh\nia-mood\`。

- `config.json`：配置和会话绑定。
- `state.json`：多份心情、时间线、已处理回合标识及注入记录。
- `diag.log`：运行诊断。

配置和状态采用临时文件再重命名写入。无法解析已有状态时停止覆盖，保留原文件等待修复。时间线不自动删除，长期使用需留意文件体积。不要让多个独立 DSH 进程同时写同一份数据目录。

回退时，关闭新插件的判断与注入并解除正式绑定，再恢复原插件设置。新旧数据目录分开，不需要删除新数据。搬到另一台电脑时，关闭写入后备份并迁移整个 `nia-mood` 目录；会话或工作区标识改变时重新绑定。

0.2.2 设置面板不提供重置按钮，不会因修改基线而清除历史或重置当前状态。

## 开发和验证

纯 JavaScript，无构建步骤，宿主代码只使用 Node 内置模块；客户端通过 DSH 模块加载器取得 React。

```powershell
npm.cmd run check
npm.cmd test
```

测试命令使用支持 `--test-isolation=none` 的 Node 版本；在本机 Node 环境验证。测试将 DSH_HOME 指向隔离的 `work/nia-test-*` 目录，使用模拟模型，不读取正式会话，不消耗真实模型额度。可通过 `NIA_TEST_ROOT` 指定测试输出根目录。

评估调用有 45 秒等待上限，超时结果不写入；同时尝试通过 signal 取消调用。底层网络请求是否立即终止取决于模型提供者是否支持取消。

测试范围包括数值衰减、输入校验、会话隔离/共享、事件去重、延迟结果失效、接口读写、以及三个设置页的模拟渲染。已在隔离浏览器中验证真实 React 页面和插件 HTTP 接口的选择、保存、刷新回读。尚未验证实际模型的主观判断质量、正式 DSH 窗口效果、QQ 桥接端到端行为。模型评估具有不确定性，设置门槛能减少错误但不能消除错误。

## 0.2.2 模型适配与诊断

修复默认判断模型依赖不存在的 agent.model.current 接口的问题。按当前选择投影、会话请求头、Agent 配置和默认模型读取；显式判断模型仍优先。支持宿主 prepareCall，并按模型实际支持情况关闭或降低推理，使用单一多人物 JSON 输出格式。
评估状态保存于 nia-mood/linked-diagnostics.json；设置页显示最近成功时间和缺少模型、超时、只有推理、格式错误等原因，不记录推理正文或原始提供方错误。失败不伪造情绪变化。当前心情按查看时刻计算时间衰减，读取不改写状态。


## 0.3.3：历史与诊断（覆盖上文旧版界面限制）

新增“历史与诊断”：选择联动或独立模式、会话和具体人物；时间线每页 30 条，可查看更早记录、原因、维度变化和来源事件。今后的联动变化不再裁剪为 100 条；旧版本已丢弃的记录不能凭空恢复。历史仍存于原状态文件中，保持备份迁移方式。

查看注入内容分别显示当前只读预览和上次宿主读取的文字及时间。联动预览使用同一生成函数，尊重原聊天私密范围；只读不消耗额度、不修改情绪。联动“上次读取”是本次插件运行的诊断，重启后重新记录；独立模式仍显示已保存的原注入记录。宿主读取上下文不等于 QQ 已发送。

“重置当前状态，保留历史”仅作用于所选整体/人物，回到基线、维度归零、追加管理记录；保留事件去重状态，过往冒犯不会因此再次计分，不能将重置理解成已原谅。并发旧评估不能覆盖重置。

“单独清空历史”与重置分开，需输入“清空历史”确认，只清时间线、当前心情不变。正式使用前可备份 nia-mood 和 nia-memory 目录。

本次保留原人格、情绪判断规则、自动 QQ 联动与状态衰减。未恢复挂饰、原仓库更新入口或旧的一次性联动注入限制。
